## 4. Key Risks (Unified Plan Level)

- **CRITICAL:** Plan drift — the unified plan was tagged v0.6-phase4 but may not reflect the current state of all 8 projects (this session's Phase 4 completions need integration)
- **HIGH:** Resource dilution — 8 projects + 3 proposed new papers + 12 new domains = ~23 work items. With finite researcher-hours, prioritization is essential
- **HIGH:** QWAV-QNFO alignment gap — the commercial strategy documents (QWAV whitepaper v4.1, Venture Prospectus) are at a different level of abstraction than the research papers; bridging this requires deliberate effort
- **MEDIUM:** Dependency cascade — if the continuum trilogy's OC criterion is refuted, the adelic program loses its foundational justification

## 5. Stage 9: Practical Applications (Meta Level)

The unified plan's "practical application" is meta-organizational: it guides which projects get resources, which get descoped, and which new projects get launched.

**Operational Signature:** Quarterly unified-plan review sessions use the qualitative rankings + vulnerability assessments to reallocate effort across projects. A project that drops in ranking (e.g., due to a refuted enabling assumption) gets resources shifted to a rising project.

## 6. Stage 10: Counterfactual Backcasting (Meta Level)

### Tier 1 Fork (~3yr): Unified Plan as Active Decision Tool from Day 1

**Fork:** The unified plan was maintained as a LIVING document from v0.1 — updated every quarter with project status, dependency changes, and resource reallocation decisions.

**Counterfactual (2026):** The "plan drift" problem never occurs. The gap between plan and reality is ≤ 1 quarter. Cross-project dependencies are tracked in real-time. New domains (like the 12 identified this session) are incorporated into the plan within 1 month, not discovered retroactively.

### Tier 2 Fork (~20yr): Formal Research Program Management for Open Science

**Fork:** Open-science research collectives adopt formal program management methodologies (analogous to DARPA program managers or CERN experiment coordination) from their founding.

**Counterfactual:** QNFO's 8 projects are managed with the same rigor as a DARPA program. Each project has a defined "success gate" and a "kill criterion." Projects that fail their success gate are terminated; resources are reallocated to projects that pass. The "resource dilution" problem is solved structurally — the management methodology enforces prioritization.
